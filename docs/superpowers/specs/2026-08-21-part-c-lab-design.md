# Часть C — аналитическая лаборатория портфеля

**Дата:** 2026-08-21
**Статус:** дизайн утверждён (устно), ожидает ревью спека
**Проект:** портфельный терминал (`dashboard.js`, Node 18+, без зависимостей)

## 1. Контекст и ограничения

Поверх существующего дашборда (сигналы, уровни, правила, календарь — фазы 0/A/B завершены)
строится аналитический слой из 10 подсистем. Жёсткие ограничения:

- **Ноль платных источников данных.** Только бесплатные API: Yahoo Finance (чарты,
  RSS-заголовки, quoteSummary), SEC EDGAR (филлинги, тикер→CIK), Wikipedia (состав S&P 500)
  и подписка z.ai GLM (единственная платная статья — уже есть).
- **Философия проекта сохраняется:** никаких npm-зависимостей. Вся численная математика —
  рукописная, с тестами на синтетике. Тяжёлые расчёты — через встроенные `worker_threads`.
- **Один пользователь, один процесс.** Расширяем текущий сервер, отдельный UI на странице
  `/lab` в том же дизайн-коде.

## 2. Решённые развилки (утверждены владельцем)

## 3. Архитектура (подход A — расширение сервера)


## 4. Фаза C1 — факторная декомпозиция (#1) и стресс-корреляции (#9)

**Данные:** дневные закрытия за 1 год — все позиции + ITOT + 10 прокси: SMH, XLK, URA,
MOO, GLD, XLE, IWM, TLT, UUP, SPY. Заливка через существующий `pool` (6 потоков + паузы),
дисковый кэш на сутки.

**#1.** Доходности логарифмические. Скользящее окно 60 дней (шаг 5) → ридж-регрессия
каждой позиции на факторы (стандартизация, λ = 1e-4·n) → беты, меняющиеся во времени;
итог — последнее окно, рядом σβ за окна (стабильность). Экспозиция портфеля = Σwᵢβᵢ,
с разбивкой по тегам-бакетам («бета к SMH 0.61, из них 0.14 — из „Реальных активов“»).
PCA корреляционной матрицы позиций (Якоби) → **эффективное число ставок**
ENB = exp(−Σ pᵢ ln pᵢ), pᵢ = λᵢ/Σλ.

**#9.** Условные ранговые корреляции Спирмена при SPX-дне < −2% против обычных дней;
коэффициент диверсификации DR = σₚ/Σwᵢσᵢ в обоих режимах. Выход — таблица
«норма vs стресс» + список позиций с самым большим ростом корреляции.

**UI /lab:** большая цифра ENB, таблица факторных экспозиций с разбивкой по бакетам,
таблица стресс-корреляций, предупреждение «реальные активы синхронизируются с рынком»
при росте корреляции > 0.2 в стрессе.

## 5. Фаза C2 — калибровка уровней (#5) и Монте-Карло (#4)

**#5.** GARCH(1,1) на 2 годах дневных доходностей каждой позиции (отдельная заливка
`range=2y`, не переиспользует годовую из #1); MLE — Нелдер-Мид по
лог-правдоподобию, 3 старта (из выборочной σ, из 0.5σ, из 2σ) против локальных минимумов.
Прогноз σ на горизонт H = 12 мес (агрегация дневной → годовой). Вероятность касания уровня
Tₖ — аппроксимация принципом отражения для дрейфового GBM + кросс-проверка MC (10к путей).
Правила: P(касания T₃ за 12 мес) < 5% → пометка «уровень-фантазия, пересчитать»; уровни
ближе 1σ годовой волатильности друг к другу → «склеить»; E[издержки ожидания] =
(1−P)·μ_год·H·wᵢ как прокси-метрика (честно помечена как прокси). Влияние на дашборд:
в тултипе pill уровня появляется P(касания); детали — таблица в /lab.

**#4.** Режимы: признаки ежедневно — уровень VIX, 20-дн. изменение ^TNX, 20-дн. доходность
SPX (стандартизированные). Гауссов HMM на 2 и 3 состояния (EM, по 5 стартов), выбор по BIC.
Симуляция: месячные шаги на `MC_YEARS`; на каждом шаге режим по матрице переходов, доходность
порта — блочный бутстрап 21-дневных блоков исторических дневных доходностей этого режима
(сохраняет автокорреляцию и хвосты); довнесения `MC_MONTHLY_USD` ежемесячно в ITOT.
10 000 траекторий. Выход: перцентили (5/25/50/75/95) терминального капитала фан-чартом,
распределение макс. просадки, P(достичь цели — опциональное поле `MC_TARGET_USD` в `.env`;
не задано — колонка не выводится), чувствительность:
(a) фактический тайминг входов против случайного DCA, (b) довнесения ×0.5/×1/×2 против
вклада стокпикинга. Считается в worker_threads, кэш еженедельно.

## 6. Фаза C3 — LLM-агенты: детектор (#2), фальсификации (#3), комитет (#10)

**Общий клиент `src/llm.js`:** `chat(messages, {schema})` → строго JSON по схеме
(zod не вводим — ручная валидация полей/типов), до 2 ретраев с уточняющим промптом,
температура 0.2; ключи `ZAI_API_KEY/ZAI_BASE_URL/ZAI_MODEL` из `.env`. Каждое обращение
логируется (тикер, задача, токены) в `data/llm-log.jsonl` для контроля бюджета.

**#2.** После факторного обновления: остаток r = факт − Xβ̂ (последний день и накопленный
за 5 дней), σ по истории остатков. Флаг |r| > 2.5σ. По флагу (cooldown 7 дней на тикер):
заголовки Yahoo RSS + последние 8-K/10-Q из EDGAR (тикер→CIK через официальный дамп
`company_tickers.json`) → GLM классифицирует
`{beta_move | idiosyncratic_temporary | thesis_damage}` + причина + задетая опора тезиса
+ confidence. Выход: иконка у строки в основном дашборде, карточка разбора в /lab,
кэш `data/cache/attribution/{t}.json`. Вердикты `thesis_damage` попадают в `data/recs.jsonl`.

**#3.** Реестр `data/falsifications.json`: `{t, thesis, conditions[], createdAt, status}`.
Создание: кнопка в /lab → GLM по тезису (заметка META + фундаменталии промптом) генерирует
3 фальсифицируемых условия (измеримых, с источником проверки). Ежеквартальный обход:
свежие 10-Q/10-K + новости → GLM-вердикт по каждому условию `{triggered, evidence}`.
Триггер → предложение пометить позицию ⛔ (человек подтверждает правкой META) + таймер
пересмотра по образцу B5.

**#10.** Еженедельный комитет: роли «бык», «медведь», «адвокат дьявола», «базовые ставки».
Каждой роли — контекст: портфель, факторные экспозиции, календарь отчётов, текущие флаги #2.
Выход — по 5 машинно-разрешимых прогнозов: `{event, prob, horizon_days, rationale}` где
event из стандартизированного набора (тикер выше/ниже X% за H дней, SPX-уровень, VIX-полоса).
Append в `data/predictions.jsonl`. Скоринг еженедельно: созревшие прогнозы разрешаются ценами
Yahoo → Brier по ролям, таблица калибровки (бакеты заявленной вероятности vs частота).
Консенсус = взвешивание softmax(−Brier); панель в /lab показывает, какая роль врёт.

## 7. Фаза C4 — данные с ограничениями: журнал (#6), базовые ставки (#7), капцикл (#8)

**#6.** Журнал `data/decisions.jsonl`: `{ts, type: buy|sell|skip|ignore_advice, t, qty,
price, rationale, tags[]}`. Ввод: модалка в дашборде (кнопка «Записать решение»);
автодетект — дифф снапшота позиций Tradernet между обновлениями → тост
«обнаружена сделка PSN +15 — объяснить?» с префilled модалкой. Еженедельный расчёт
контрфактуалов (возраст решения > 30 дней): фактический путь против альтернатив
(держал / равновес вотчлиста / единовременная покупка вместо DCA) по истории Yahoo.
«Точность советов»: `data/recs.jsonl` (авто-лог #2/#10) против реализованных исходов.
UI /lab: таблица контрфактуалов, кумулятивный added-value стокпикинга и советов системы.

**#7.** Вселенная: парсинг таблицы S&P 500 с Wikipedia (раз в квартал). Бэкфилл:
`chart(t,'10y')` на ~500 тикеров через pool с дисковым кэшом (одноразово, ночью).
Эмпирические классы событий: просадка ≥ 40% от скользящего 52-нед. максимума → форвардные
доходности 1/3/5 лет (от даты события и от донышка); шок-день ≤ −15% → форвард 1/3/6 мес.
Агрегаты в `data/baserates/events.json` (медиана, квартили, доля восстановившихся).
Уход CEO, разводнение, кластеры инсайдеров — только LLM-приор с литературной оговоркой.
Запрос в /lab: текст события → GLM извлекает класс и квалифаеры → эмпирическое распределение
(если есть) + LLM-приор; **каждая цифра помечена источником, эмпирика — баннером
survivorship bias** (вселенная сегодняшних живых участников).

**#8.** Месячный композит из бесплатных рядов: z-скоры 60-дн. относительной силы SOX/SPX,
URA/SPX, XLE/SPX, корзины полуоборудования (AMAT+LRCX+KLAC) против SPX, уровень TLT.
Ежеквартально: EDGAR 10-Q/10-K гиперскейлеров (MSFT, GOOGL, AMZN, META, ORCL) → GLM
извлекает капекс поквартально → нормализованный индекс капекса; ручной слот для цен аренды
GPU (textarea, значения в историю). Выход: стадия цикла 0–3 с историей, маркер «где мы
относительно kill-switch 2 из 3». UI /lab: график стадии + компоненты композита.

## 8. Тестирование

- **Математика — TDD на синтетике с известными ответами:** беты восстанавливаются из
  сгенерированных данных; собственные значения Якоби сходятся к аналитическим; GARCH
  оценивается на симулированной GARCH-последовательности (параметры ±доверительный интервал);
  HMM на склеенных двух режимов; блочный бутстрап сохраняет автокорреляцию (тест Льюнга-Бокса
  не вводим — сравнение автокорреляционных функций); барьерная вероятность против MC.
- **Парсеры** (RSS, EDGAR, Wikipedia) — фикстуры без сети.
- **LLM-клиент** — записанные фикстуры ответов (валидный/невалидный JSON/ретрай).
- **Интеграция:** smoke-запуск сервера, `/lab` отвечает, фоновые задачи не блокируют
  основной дашборд (проверка времени отклика `/api/data` при запущенном worker).

## 9. Риски и честность

| Риск | Митигция |
|---|---|
| Survivorship bias в #7 | Явный баннер в UI, эмпирика никогда не смешивается с LLM-приором визуально |
| Рукописные численные методы | Синтетические тесты с известными ответами, мультистарты, кросс-проверки (барьер vs MC) |
| ЛLM-галлюцинации | Строгие JSON-схемы, каждое утверждение помечено источником, Brier-скоринг ролей со временем |
| Лимиты Yahoo | Существующий pool + дисковый кэш + ночные бэкфиллы |
| Блокировка event loop | worker_threads для MC и PCA; лёгкие задачи чанками |
| Расход подписки | Лог llm-вызовов, каденции «экономно», ручной режим всегда доступен |

## 10. Порядок реализации

C1 (#1, #9) → C2 (#5, #4) → C3 (#2, #3, #10) → C4 (#6, #7, #8).
Каждая фаза — отдельный план (`writing-plans`) и отдельные коммиты. Долгоживущие логи
(#6 решения, #10 прогнозы) включаем как можно раньше — данные копятся, пользу даю потом.
