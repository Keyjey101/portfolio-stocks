# 05. LLM-слой: агенты, промпты, схемы, русификация

## 5.1. Клиент и вызовы

OpenAI-совместимый клиент (в оригинале z.ai GLM-5; параметры LM: `max_tokens=8192,
temperature=0.7, num_retries=2, timeout=90`). Два режима вызова:

1. **Structured (tool-calling)** для бизнес/оценка/риск: схема工具а + `tool_choice`;
   если модель вернула прозу вместо tool_calls — повтор с явным JSON-инструктажем;
   затем robust-парсинг (tool_calls → JSON-извлечение из текста → regex).
2. **Plain JSON** (только «верни валидный JSON») для news radar, 10-K-саммари,
   self-critique, advisor.

Во **всех** системных промптах присутствует привязка времени: *«Текущий год —
{YYYY}. Используй только данные {YYYY-1}–{YYYY}.»* — иначе модель путает «сегодня».

## 5.2. Русификация (требование нового проекта)

В оригинале язык управляется `?lang=en|ru`; в реплике **всегда ru** — при инициализации
агента выставляется режим «русский», эквивалентный оригинальной инструкции:

**В системный промпт каждого агента добавляется:**

> ОБЯЗАТЕЛЬНОЕ ТРЕБОВАНИЕ К ЯЗЫКУ ОТВЕТА: Весь текстовый контент в ответе
> (описания, пояснения, рассуждения, инсайты, риски, катализаторы, нарративы,
> резюме, причины, комментарии) ДОЛЖЕН быть написан на русском языке. Ключи JSON
> и числовые значения остаются без изменений. НЕ пиши текстовые значения на
> английском — только русский язык.

**В каждый user-промпт добавляется суффикс:** «Ответь на русском языке. Все
текстовые поля JSON — на русском.»

Детерминированные строки (framing, assumptions, фоллбек-тексты) в оригинале
генерятся кодом на английском — в реплике их следует сразу писать на русском
(см. `10-improvements.md`, §1). Кэш-ключ включает язык.

## 5.3. Агент Business (качество бизнеса)

System (суть): «Ты — аналитик	long/short хедж-фонда, специализирующийся на
качестве бизнеса и конкурентных преимуществах. Оцени бизнес-модель, источник
устойчивости прибыли (moat) и траекторию отрасли. Будь конкретен и скептичен,
не пересказывай описание компании. Текущий год — {YYYY}…»

Контекст (user): компания/сектор/индустрия, описание ≤400 симв., выручка за 5 лет
строкой, CAGR 3 г., тренды, средние маржи и ROIC за 5 лет, доля FCF-положительных
лет, P/E trail/fwd, EV/EBITDA, тег цикличности, контекст новостей (6 мес).

Выход (`BusinessOutput`):

```json
{
  "business_model": "…",
  "revenue_type": "recurring|transactional|project-based|cyclical|mixed",
  "moat_type": "switching_cost|network_effect|brand|cost_advantage|intangible_assets|efficient_scale|none",
  "moat_description": "…",
  "moat_score": 8,
  "industry_trend": "growing|stable|declining|disrupted",
  "industry_cyclicality": "secular|mild_cyclical|highly_cyclical",
  "industry_score": 7,
  "business_score": 8,
  "key_insights": ["…", "…"],
  "concerns": ["…"]
}
```

`moat_score/business_score/industry_score` — 0–10. max_tokens 2048.
Фоллбек: `_fallback: true`, все скоры 5, enum'ы — «unknown», тексты
«Анализ временно недоступен». Оркестратор делает **1 retry**, затем фиксирует деградацию.

## 5.4. Агент Valuation (нарратив поверх готовых чисел)

Ключевой принцип: **модель не считает и не меняет числа.** System (суть): «Ты —
специалист по оценке в long/short хедж-фонде. Справедливая стоимость УЖЕ посчитана
детерминированной мульти-методной моделью (двухстадийный DCF, EPV, обоснованные
P/E и EV/EBITDA, число Грэма, дисконтированная цель аналитиков). НЕ пересчитывай
и не оспаривай предоставленные числа — интерпретируй их. Реалистично относись к
циклическим пикам против нормализованной прибыли. Текущий год — {YYYY}…»

Контекст: ров (из business), `base/bear/bull`, `expected_value` с вероятностями,
MoS, разбивка методов с весами, допущения (g, WACC, терминальный рост), цель
аналитиков + PV, цена, капитализация, мультипликаторы, CAGR, ROIC, консенсус-диапазон.

Выход (`ValuationNarrative`, max_tokens 1200):

```json
{
  "relative_assessment": "…относительно сектора и собственной истории мультипликаторов…",
  "valuation_narrative": "…2–4 абзаца интерпретации…",
  "dcf_assumptions": "…популярное перечисление ключевых допущений…",
  "is_cyclically_adjusted": false
}
```

Фоллбек: детерминированный однострочный нарратив; **флаг `_fallback` не ставится**
(математика уже готова — прогон не считается деградированным).

## 5.5. Агент Risk (инвестиционный тезис и mispricing)

System: «Ты — портфельный менеджер, пишущий внутренний меморандум. Объясни, почему
акция дешёва или дорога, что рынок упускает, структура ли это или временное
явление. Один разовые прибыли искажают trailing P/E — сравнивай forward и trailing
осмотрительно. Текущий год — {YYYY}…»

Контекст: бизнес-оценка, качество финансов (CAGR'ы, тренды, ROIC, FCF, долг,
Piotroski), траектория EPS «простым языком» (forward vs trailing — гард от
инверсии), блок оценки (цена, base/bear/bull, MoS, мультипликаторы), **полный**
SEC-блок, **полный** блок сентимента.

Выход (`RiskOutput`, max_tokens 2048):

```json
{
  "why_cheap_or_expensive": "…",
  "is_temporary_or_structural": "temporary|structural|fairly_valued",
  "what_market_misses": "…",
  "mispricing_type": "opportunity|value_trap|fairly_valued|overvalued_justified|overvalued_bubble",
  "catalysts": ["…"],
  "key_risks": ["…"],
  "time_horizon": "6-12 months|1-2 years|3-5 years|>5 years",
  "thesis_summary": "…",
  "risk_score": 4,
  "sec_filing_assessment": "…",
  "sentiment_interpretation": "…"
}
```

`risk_score` 0–10 (10 — макс. риск). Фоллбек: `mispricing_type: fairly_valued`,
`risk_score: 5`, `time_horizon: unknown`, пустые списки, `_fallback: true`.

## 5.6. Прочие вызовы

| Вызов | temp / max_tokens | Выход |
|---|---|---|
| News radar | 0.2 / 500 | `{risk_level, events[], summary}` (см. `02`, §2.4) |
| 10-K MD&A | 0.1 / 512 | `{mda_summary, top_risks[3–5], filing_tone}` + кейворд-фоллбек |
| Self-critique | 0.3 / 512 | `{bear_case, confidence_adjustment, missed_risks, final_assessment}` (см. `04`, §4.5) |
| Scanner advisor | 0.7 / 500–600 | текст-саммари по top-5 строкам скана (+предупреждение о кластеризации, см. `06`, §10) |

## 5.7. Общие правила устойчивости

- Таймаут 90 c на вызов, 2 ретрая; при rate-limit — backoff 60 c.
- Content-filter отказ — пометить и пропустить (для news), не ронять пайплайн.
- Все JSON-выходы валидируются pydantic-схемой; невалидные поля → дефолты схемы.
- Числовые поля LLM **никогда** не переопределяют детерминированные: MoS/score
  пересчитываются кодом после LLM-фазы (оркестратор), вердикт зависит только от кода.
- Затраты: полный анализ = 6 вызовов (business, valuation-нарратив, risk, news,
  10-K, self-critique опционально). Сканер: 2 вызова на тикер (business + valuation-нарратив)
  только для top-N, плюс 1 advisor на скан и по 1 news-классификации на тикер пула.
